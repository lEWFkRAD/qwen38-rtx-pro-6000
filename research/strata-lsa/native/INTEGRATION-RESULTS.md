# Native Strata LSA integration results — November 3, 2026

The opt-in native LSA engine integration is complete and passed the recorded functional gates. It covers prompt prefill, single-token decode, speculative verification, accepted-prefix reuse, slot copying and restored-cache reconstruction. The same-model performance gate was **not met**. The candidate remains an isolated research build and was **not promoted to production**.

The final full candidate run completed at 16:42 EST; the API compatibility canary completed at 16:45 EST. Production Qwen remains intentionally paused under maintenance owner `example-lsa-maintenance-owner`. Sunshine remains stopped with its startup setting unchanged. The private test process group exited and its temporary credential file was removed. This report does not claim production was restored.

The final engine canary preserves native attention while using learned projections, native Ward closure and LSA selection in all three inference paths. Batched prefill, a parallel integer expansion and shared-input projection avoid the initial per-query launch and serial-expansion bottlenecks. The final results above include those changes. The remaining decode and batch slowdown is still material to the promotion decision.

**Retained API and vision behavior.** The private API canary passed authentication rejection, exact plain text, a forced tool call with the exact expected arguments, high-reasoning arithmetic with a separate reasoning field, and a newly generated image's center-square color. It used the retained production Python wrapper and the official matched vision encoder with the isolated candidate decoder. Eight slots, full context/KV/expert residency, `fit_max_tokens`, soft reasoning recovery and close retry were retained.

For this private canary only, `ONYX_STRATA_READINESS_GATE=0` bypassed wrapper admission checks whose protected paths deliberately refer to the paused production process. Production's admission gate and recovery contract were unchanged. The replacement test admission checks verified the exact owned HOLD and inactive production throughout, a loopback-only listener with a fresh undisclosed random API key, exact wrapper/decoder/encoder process identities and arguments, retained model capacity before inference, unchanged production configuration/contract hashes and synthetic-only requests. This was an isolated compatibility test, not a production-readiness receipt or a deployment.

The promotion decision is **no promotion**: integration works in the tested scope, but the complete candidate has not demonstrated an overall performance improvement. The production serving JSON remains pinned at `a73d0dc2ddbf644d1d9f7520d639499e73c7c0f71d38e3d502a05d540464d4a9` and its recovery contract at `998954a2bf7f26634dead0950d4b52bb16041d6a7b4d609da7661bb38a14c911`.
